## Where it stands

A spike is a question with a budget, and it can't ship code. A person, or
the chat agent with `create_spike`, writes a spike down on an initiative or a
feature. **Only a person starts it, in the web UI**, from a start screen that
shows who will run it, the budget, what the agent will be given (the question,
the decisions that apply, its tools) and where it works. One agent, the new
`spike-runner`, works on the question in a **detached** worktree and saves its
findings as it goes. The dispatcher **stops the run hard at its token
budget**: it never begins a call it can see would cross the budget. When the
run ends, for any reason, the server writes the findings document from what
was saved, commits it, checks that no code was kept on a ref, and **discards
the worktree**. A person reads the findings and closes the spike as answered
or not, or asks again with a second, separately budgeted spike.

**The roadmap's done-when — a spike hits its budget and stops, and nothing can
merge its code — is two tests, `TestSpikeStopsHardAtItsBudget` and
`TestSpikeHasNoMergePath`, and both pass.** The suite is green with the race
detector, the browser demo ran with no AI provider, and the verifier found
every acceptance criterion evidenced.

**Stage 2 (spikes run by the chat AI or a person, held to a time box) is
specified in SPEC-021 §4 and not built**, because M13 hasn't merged into
`main`. It is the remaining work, below.

**Nothing waits on Sam to merge**, by the orchestration note's rule. SPEC-021
waits for Sam's approval, with fourteen choices (its DoD 10).

## What was built

**The entity (FR-1).** `spikes`, its own table, not a feature row (SD-1):
`SPK-nnn`, an initiative and optionally a feature, the question, four states
(`idea`, `running`, `ended`, `closed` as answered or unanswered), the
budget and tokens used, the draft, how the run ended, the worktree, the refs
at the start, and who and when. Twelve named checks. `ref_type` gains `spike`
and `document_type` gains `findings`.

**The findings (FR-2).** `templates/findings`, approved by a person, with no
agent reviewer. The document, `SPK-003-findings`, is **created when the run
ends**, from the draft the agent saved on the spike's row, so nothing can
submit or edit half-written findings (SD-9). The server writes the Question
from the row and **How this spike ended** last.

**Starting (FR-3).** `/ui/spikes/start`: the screen and its `POST`, which
moves the spike to running with a conditional update, records the budget and
the refs, and queues the run. No API route, MCP tool, agent tool or
checkpoint answer starts a spike.

**The run (FR-4).** The `run-spike` purpose on the `spike-runner` role: the
surfaced decisions first, the question, the owner, the earlier findings for a
spike that asks again, the draft for a retried attempt, the budget sentence,
and the working copy's rules. The planner makes the detached worktree before
the first call. `save_findings` writes the draft; `finish_spike` concludes.

**The budget (FR-5).** `dispatch.Plan.Budget`: the database's running total,
added to straight after each call; a check before every call, with a lower
bound for the next; save tools run on the turn that crosses the budget; the
turn cap as a stop; a `stop` entry in the transcript. A plan without a budget
runs exactly as before.

**Ending (FR-6).** `EndSpike`, re-runnable from any step: the leak check, the
findings and the state in one transaction, the commit, the discard.
Exhaustion ends the spike instead of asking "Retry or cancel?". Reconciliation
runs at boot and on every heartbeat.

**The leak check (FR-6.3, amended twice).** It reads the worktree's own
reflog from git's administrative copy, keeps the commits made there, and
reports any ref that changed during the spike and holds one, plus any new tag
or stash. It fails closed. `TestSpikeHasNoMergePath` covers twelve cases.

**Closing (FR-7).** The question is answered, close without an answer, or ask
again, which closes the first spike and writes down a second.

**Where spikes show (FR-8).** The spike's page, the owner's **Spikes**
section, `/ui/spikes`, the Inbox line, spike moments as muted asides on the
feature's timeline, the run page's purpose, crumbs and outcome. Not milestone
deliverables.

**MCP (FR-9).** `create_spike`, `list_spikes`, `get_spike`, and eight more
forbidden names in the tool-set test.

**The pack and config (FR-10).** `spikes.default_token_budget` (1,000,000),
`run-spike: spike-runner`, the role, the skill, and the loader's checks.

## Decisions taken in the build

These are beyond the spec, or settle what it left open. Each is recorded
where the code is.

- **A run that stops below its budget** (the lower bound ruled out the next
  call) says so: "The spike stopped at its budget, because its next step would
  have gone over. It used 19,944 of its 20,000 tokens."
- **`finish_spike`'s findings are saved as the draft**, and the findings are
  always written from the draft, so there is one write-up path and a resumed
  ending writes the same thing.
- **The findings are committed only if the file isn't in `HEAD`**, so a
  heartbeat never sweeps a person's later edits into a commit.
- **A planner refusal** (a spike that isn't running) is an ordinary attempt
  error. The dispatcher has no permanent failure, so it retries until
  exhausted, and `EndSpike` is then a no-op.
- **`EndSpike` is serialised** by a mutex, and the heartbeat's reconciliation
  notifies the browser only when it changed something.
- **Start and close redirect** to the spike's page with `?did=`. The page says
  only what the spike's state confirms, so a crafted `did` shows nothing.
- **The G5 refusal names the open spikes**: "SPK-002 and SPK-004 are still
  open".
- **The `spike-code-kept` checkpoint's answer is "I've dealt with it"**, a new
  verb, `dealt_with`, which changes nothing in Subutai.
- **`TestRenderedTemplatesCarryNoCurrency`** lets `spike.html` say "budget":
  a spike's budget is tokens. The currency checks still apply to it.

## Where the brief conflicted with an approved document, or went further

- **The roadmap's done-when says nothing can merge a spike's code.** Subutai
  has no path that does (SD-2), but an agent can run code it wrote through
  the project's whitelisted commands, and that code can make a branch. So
  "enforced, not promised" (DESIGN-010 §10) is met by the absence of any merge
  path plus a leak check that reports kept code. SD-2 and FR-6.3 say so, and
  FR-6.3 names what the check can't see.
- **DESIGN-010 §7 says creating work creates its documents.** A spike's
  findings are created when its run ends, not when it is created, because a
  draft document a person could submit while the agent writes it caused every
  REVIEW-021 R21-1 problem. §7 names initiatives and features; SD-9 says why a
  spike differs. Choice 8 asks Sam.
- **DESIGN-010 §10 says a chat or human spike's time box is "enforced through
  claim expiry".** DEC-007 decision 6 defines claim expiry as an inactivity
  checkpoint. SPEC-021 S2-6 reads both: the time box is the claim's *hard*
  expiry, a deadline fixed at the start, and M13's inactivity checkpoint still
  applies before it. Choice 14 asks Sam. Stage 2 builds it.
- **The brief says a human decides whether to ask again "on the stop".** The
  ask-again action is on every ended spike, not only one that stopped at its
  budget, because a concluded spike can still leave the question open.
- **The orchestration note names Sonnet 5.5**; Sonnet 5 is what ran, as the
  note itself says.

## Bug-report candidates (minor findings still open)

From the three review rounds and the verifier, ready for the triage queue.
None is a major.

1. **A leak recorded before a retry's remake is final**: a branch made in the
   remade working copy isn't added to the record (round 3, N1).
2. **The check before a remake doesn't re-read the spike under the lock**: a
   narrow race can raise a false `spike-code-kept` checkpoint on a spike that
   ended cleanly (round 3, N2).
3. **Only a leading `#` is escaped in the findings' Question**: a question
   starting with `- `, `> `, `1. ` or `|` renders as Markdown structure
   (round 3, N3).
4. **Findings for a question containing "TODO" or `{{…}}` fail
   `lifecycle.Validate` on disk**, though the run concludes and the question is
   kept as asked (rounds 1–3). Either exempt the Question in the manifest or
   accept it in FR-2.1.
5. **Tokens can be added to an ended spike** by an attempt that was given up
   on, so the page and the findings can disagree by one call (rounds 1–3).
6. **One `rev-list` per changed ref** in the leak check; a scale concern on
   repositories with many moving refs.
7. **`get_spike` with no `spike` argument** answers "there is no spike """
   rather than saying the argument is needed.
8. **`turnCapFor`** isn't used at the four older turn-cap sites in
   `planner.go` and `documents.go` (left to avoid conflicts with M13).
9. **Generic names in package `server`**: `numField`, `strField`, `setOf`,
   `isSHA`, `reason`, `canonPath`, and the template func `code`.
10. **Test helpers `wants` and `lacks`** shadow each other's names.
11. **Timeline asides use state `idea`**, so they take the idea colour.
12. **`writeFindings` builds the text up to four times.**
13. **`gitInWithStdin` duplicates `gitIn`**, and sits in `planner.go`.
14. **The `spikeEndMu` lock and unlock** is written out three times.
15. **`groupThousands`** is now a one-line wrapper; `lifecycle.joinIDs`
    duplicates `joinWords`.
16. **The start screen's `Workers`, `Running` and `Free`** could be one value.
17. **Test structure**: the `#` question case is tacked onto the TODO test;
    `TestSpikePostsAnswerBadIDs` doesn't close one response body; some case
    names read like typos; one redundant raw-SQL count.

## Traps for the next session

- **A spike isn't a feature row.** Nothing in the feature pipeline sees one,
  by design. Code that lists "work under an initiative" must ask for spikes
  separately, as G5 does.
- **The findings don't exist until the run ends.** Code that wants a spike's
  findings before then reads `spikes.draft`.
- **`EndSpike` runs from the rules, the heartbeat and boot.** Keep every step
  safe to repeat.
- **`refs_at_start` is written at the start.** A spike started before this
  column existed can't be checked, and fails closed.
- **The mock provider is one FIFO.** A spike test that also runs other
  dispatches scripts them in order.
- **Run parallel test suites with `SUBUTAI_TEST_DB_SUFFIX`**, or the server
  harness drops another checkout's schema.
- **A project served from a long path won't start** (the 108-byte socket
  limit). The demo used `/var/tmp/m14demo`.
- **This branch should be deleted after the merge.** If this session can't,
  the command is `git push origin --delete claude/subutai-m14-spikes`.
