**Not built:**

  correctness** — but the heartbeat is not wired to the reconciler yet either.

## Decisions taken during the build that a reader should not undo

**The chain ships opt-in.** `write-spec` and `write-dev-plan` are commented out
in the starter's `assignments`. Enabling them by default queued an authored
dev-plan into **seven** existing tests that write their own — which is the
feature working, and exactly why it must not switch on under projects that never
asked. Revisit once Stage 1 is complete and smoke-tested; do not flip it
casually.

**An unassigned authoring purpose is silence, not a checkpoint.** A project that
writes its own dev-plans is working, not broken. The first draft raised a config
error and would have made every existing project complain on upgrade.

**An undescribed feature is never dispatched and never checkpointed.** In
width-first planning a placeholder feature is normal. Same principle.

**Authoring dispatches carry a nil `ToolCtx`.** Documents live in the main
repository, never a worktree. This is the property most likely to be eroded by a
later change.

**The required structure comes from the manifest, not the template file.** There
is no template loader. Using the manifest means what the author is told to
produce and what validation checks are the same thing by construction.

## Traps this session hit, so you needn't

- **`go test ./...` proves much less than it looks.** Integration tests skip
  silently unless `CROMWELL_TEST_DATABASE_URL` is set. **Four UI tests had been
  failing for four days** undetected, including `TestUIBrowseAndDrive`, which
  SPEC-007's DoD names. Always run with it set:

      CROMWELL_TEST_DATABASE_URL="postgres://postgres:cromwell@localhost:54329/postgres" go test -race ./...

- **Never point that at `CROMWELL_DATABASE_URL`.** That variable holds a *remote
  Supabase* instance, and `testdb` creates and drops databases. Use the local
  `cromwell-pg-dev` container on 54329.
- **The Browser pane reports `innerWidth: 0` when hidden**, and every rectangle
  is then a lie. Call `resize_window` first and assert it is non-zero — this bit
  again this session even though the previous handoff warned about it.
- **`internal/gitwatch/` is an empty directory.** The watcher named in the
  vision's architecture is the git post-commit hook. It only ever sees *commits*,
  so it cannot see an agent's uncommitted write — which is why
  `submit_document` notifies directly.
- **`git add -A` swept a code slice into a docs commit.** Stage explicitly.

## The discipline, unchanged

Author a planning package → do an authoring consistency review → **Sam approves
before any code**. Never self-approve a package you wrote. It caught four
material problems in SPEC-009 this session, one of which — nothing triggered the
dev-plan — would have made the spec's load-bearing claim false on its first run.
