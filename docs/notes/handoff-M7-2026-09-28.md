## The compatibility rules, and when they end

All are in SPEC-013 §3. In short:

- **Folder.** `.subutai/` first, then `.cromwell/` with a warning. Both: use
  `.subutai/` and warn. `init` refuses either. Under `.cromwell/`, the default
  socket keeps its old name, so a Cromwell binary still reaches the server.
- **Variables.** Each `SUBUTAI_*` read falls back to its `CROMWELL_*` twin with
  a warning; the new name wins. A `url_env` naming either twin reads the pair,
  and one naming the old variable gets its own warning.
  `scripts/test-db.sh` exports **both** names, so an older branch in a new
  session still finds its database.
- **Worktrees.** One recorded under `.cromwell/` is followed into `.subutai/`
  after the rename, by the server and by the agents working in it, and
  repaired in git on start (git 2.29 or later). So the folder can be renamed
  while features are building, with the server stopped.
- **Header.** `X-Cromwell-Actor` is read when `X-Subutai-Actor` is absent.
- **The post-commit hook.** `serve` rewrites a hook `init` wrote when it is
  Cromwell's, names a binary that is gone, or names another repository. It
  leaves edited hooks alone (saying which line to change), never writes a
  `go run` binary into the hook, and doesn't flip between two installed
  binaries. **This one stays** after the fallbacks go: it also fixes a project
  whose binary moved.

**When they end:** in the first milestone after "Subutai usable" (SPEC-013
§4; that's choice 2). The removal is `grep -rn 'compat(M7)'` plus the
`internal/compat` package, keeping `Folder`, `HasFolder`'s first check,
`Getenv`'s first read, and the hook refresh.

## Renaming the GitHub repository

This is yours to do; nothing in the code depends on it. The Go module is the
bare name `subutai`, not a repository URL, and no file names the repository's
URL (checked with `git grep`).

1. On GitHub: **Settings → General → Repository name**, `cromwell` to
   `subutai`, then **Rename**. GitHub redirects the old web and git URLs, but
   don't rely on the redirect for long: it breaks if a new repository ever
   takes the old name.
2. In each clone: `git remote set-url origin https://github.com/sambeau/subutai`
   (or the SSH form).
3. **Claude Code on the web.** A GitHub App's access is to the repository,
   not its name, so it should carry over; check the repository still shows
   under the Claude app's access at github.com/settings/installations. Start new sessions and
   environments from `sambeau/subutai`; sessions already open keep their
   checkout until they end.
4. **Branch protection, secrets and Actions settings** move with the
   repository. The CI workflow names no repository, so it needs nothing.
5. Optionally, rename the local folder of your clone, and your Docker container
   `cromwell-pg-dev` (then update the manual testing guide, which names it).

## Decisions taken in the build

- **The compatibility code is one package**, `internal/compat`, with one
  resolver for the folder, one `Getenv`, and one worktree-path rule. Every path
  derives from the folder it returns, so no caller hard-codes `.subutai`.
- **Warnings go to standard error, once per process**, on one line each, and
  start `warning:`. The hook's own output goes to `/dev/null`, as before.
- **The rename commit is mechanical.** It changed names only; everything that
  behaves differently is in the compatibility commit.
- **Identifiers that don't name the product were left alone**, such as
  `CompartmentRoot`. A code comment that told history ("Cromwell had none of it
  before SPEC-009") now says "this project".

## Traps for the next session

- **Branches cut before M7 import `cromwell/internal/…`.** Merging one into
  this branch conflicts on every import line. Rename the imports on the other
  branch first: `git ls-files '*.go' | xargs sed -i 's#"cromwell/internal/#"subutai/internal/#g'`,
  `git mv cmd/cromwell cmd/subutai`, and `module subutai` in `go.mod`.
- **Code on such a branch that reads `.cromwell/` directly** (a test helper
  such as `editConfig`) will look in the wrong folder after the merge. Search
  the incoming diff for `.cromwell` and `CROMWELL_`.
- **Your shell may still have only `CROMWELL_TEST_DATABASE_URL`.** It works,
  with a warning; a session started before this branch has only that one.
- **`pkill -f` in a demo script can kill the script's own shell** if the
  pattern matches its command line, as M3 found. Kill by process id instead.
- **A project served from a long path won't start** (the unix socket's
  108-byte limit), as before. The demo used `/var/tmp/m7demo` and
  `/var/tmp/m7old`.
- **`gofmt -l` lists three files** (`internal/lifecycle/task_test.go`,
  `internal/server/integration_send_test.go`, `internal/toolhost/toolhost.go`).
  They were unformatted before M7; this branch didn't touch their formatting.
