## Where it stands

moment opens to the run that caused it and the runs in its phase, and each run
opens to its full transcript: what the agent was told, every turn and tool
call with its result and latency, and what it concluded. Every run's

## What was built

**Transcripts** (`internal/store/transcripts.go`, `internal/dispatch/transcript.go`):

- A `transcript_entries` table, one row per entry: the prompts once, each turn
  with its tokens and model latency, text, tool calls, tool results with their
  latency, nudges, the outcome, and errors. Keyed by run and **attempt**,
  because a retry reuses the dispatch row.
- Every failure path (loop error, stall, refusal at admission) ends its
  attempt's transcript with the reason, written by `MarkDispatchFailed` in a
  savepoint so it can never stop the failure being recorded.
- Limits, in a new optional `transcripts:` section of `config.yaml`:
  `max_prompt_bytes` (1 MiB), `max_tool_result_bytes` (32 KiB),
  `max_entry_bytes` (256 KiB), `max_attempt_bytes` (4 MiB), and
  `retention_days` (180; 0 keeps for ever). Over-long entries are cut in the
  middle with a marker, never dropped; NULs and bad UTF-8 are cleaned.
- An hourly heartbeat duty prunes old transcripts and marks the run; the
  outcome, tokens, and tool ledger are kept.
- `tool_calls.latency_ms` is now measured, not 0.

**A run given up on stops** (SPEC-012 SD-15): the loop checks its own attempt
is still current before and after each model call, and success is recorded
only for the current attempt (`MarkAttemptSucceeded`). Before, a run failed by
the stall sweep kept going and could record its outcome over its own retry.

**The timeline** (`internal/timeline`, pure): one mapping table turns audit
events into moments; each moment an agent caused links to the run that caused
it; runs are placed in the phase current at their first queue row; people and
the chat agent are attributed by name. On the feature page it sits between the
head and the body, and replaces "Recent activity" there.

**The transcript viewer**: `/ui/run/{id}` (and `?attempt=N`).

**Run lists**: "Agent runs on this task" on task pages, "Agent reviews of
this document" on document pages.

**Review health** (`internal/reviewhealth`, pure): `/ui/review-health`, with
a card on Home.

## Decisions taken in the build

- **The timeline is a pure package with a table**, not SQL. It is table-tested
  without a database, and a new kind is one entry.
- **A moment's cause is the latest run of the named purposes, on the same
  document or task or on the feature, that finished at or before the event.**
  Verdicts are applied in the transaction after the run's success, so this is
  exact for the loop as it stands.
- **The live refresh swaps only the line of moments**, and a running run's
  page polls only a status line, so nothing a reader opened closes (R12-8).
- **Failures are shown as a sentence chosen by kind**, with the engine's text
  in a disclosure.
- **Review health is cards, not a table** (D-10), with a sentence under each
  figure.
- **Template helpers are added from `observe.go`'s `init`**, so `ui.go` changes
  only by its routes.

## Where the brief was wrong or went further than the design

- **"Keeping `entity.html` changes to an include and a small hook"** — the
  timeline is one include, but the task and document run lists are one more
  each. The feature page's "Recent activity" needed no template change.
- **The brief put review health on "the dashboard, or a small page linked from
  it"**; both were built: the page, and a card on Home.
- **Review health "per reviewer"** in DESIGN-010 §8 is narrowed to agents
  (choice 2). The design wins where it binds, so this is put to Sam rather
  than assumed.
- **The timeline above the body** adds to DESIGN-008 §5.2 (choice 6).
- **The stall behaviour (choice 9)** wasn't asked for, but transcripts made it
  visible: a run declared dead kept writing after its own error, and could
  mark its retry succeeded.

## Live smoke for Sam

With a real provider, on the smoke project:

1. `scripts/smoke-project.sh` to rebuild the smoke project, then serve it.
   Its database takes migration `0008` on start.
2. Take one feature through: approve its spec and plan (or let the authoring
   chain write them), then **Start work**, and let it run to done.
3. On the feature's page, read the line of moments. Open **What happened at
   each step**. Check that *Spec approved* and *Done* each say what led to
   them, and that the runs in *Building* are the implementers and code
   reviewers.
4. Open a code review's transcript. Check the prompt under **What it was told**
   is the whole assembled prompt, that each turn's tokens look right against
   the provider's own numbers, and that tool calls show real latencies.
5. While a run is going, open its page: the status line should count turns
   and offer to reload, and an opened tool call should stay open.
6. Open **How the reviewers are doing** from Home. With real models, times to
   verdict will be tens of seconds and nothing should be flagged; if a
   reviewer is, read its transcripts.
7. Check sizes: `SELECT d.purpose, sum(octet_length(t.content)) FROM transcript_entries t JOIN dispatches d ON d.id = t.dispatch_id GROUP BY 1;`
