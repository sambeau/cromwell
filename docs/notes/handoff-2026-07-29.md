## What exists now

**Stage A (SPEC-007).** Every initiative, feature and document is a page at a
readable URL (`/ui/i/auth/login`). The entity's main design document is the body
of its page; specs and dev-plans are agent-facing and never featured. Actions
live on the thing they act on — no entity is addressed by a typed path anywhere.
Work is in tokens throughout, with a confidence ring and an explicit "not
estimated yet". Migration `0005` gave milestones and roadmaps an owner, so
planning is local to the level it belongs to.

**MCP slice 1 (SPEC-008).** The chat agent can create and edit initiatives and
features, set titles and descriptions, and attach documents — and nothing else.
The DEC-004 line is enforced *by omission*: no tool exists that starts a feature,
touches a gate or spawns an agent, so none can be called.

**The design system**, five rounds with a designer, is applied over both. The
stylesheet and a 75-symbol sprite ship embedded in the binary. Icons and the
confidence ring are em-sized so they track their type. The rail scopes rather
than nests, so depth is free.

## Things the next person must know

**Two open questions that should be answered before code, not during:**

- **`dispatch_review` and `checkpoint_respond`** — vision §7 lists these as MCP
  tools, but one spawns an agent and the other can answer a gate, so both appear
  to **conflict with DEC-004**. Do not write them and hope. Decide the boundary
  first. Flagged in `spec-008-slice-2-entry-criteria.md`.
- **Document *submission* is still CLI-only** (`doc submit`, `doc revise`). It is
  on the DEC-003 removal checklist as **not covered** by any UI or MCP surface,
  so the CLI cannot fully retire until Stage B or a later MCP slice takes it.

**Rules that are load-bearing, not preferences:**

- **The UI gains no authority.** Every mutation is an existing gated, audited
  service method, in-transaction with its audit row. The redesign moved buttons;
  it never touched who may do what.
- **No money on the human surface.** Work is tokens. The engine still has a USD
  ledger and a price table, deliberately dormant (DESIGN-008 Q-C). There is no
  currency formatter in the template helpers, and its absence is what keeps
  money off the surface — a test asserts no rendered page carries currency.
- **No entity addressed by a typed path.** A test greps for it.
- **Human-facing prose** (headings, descriptions, labels, gate reasons) is
  written in full sentences for a designer/product reader. Specs and dev-plans
  are the only place terse agent-to-agent writing belongs.

**Traps this session fell into, so you needn't:**

- **`.panel` and `.section` are the same component.** Nesting one in the other
  draws a card inside a card. Cost one visible bug and seven invisible ones.
- **A CSS class that does not exist fails silently.** `u-mb-2` is not in the
  utility scale (`u-mt-2/4/6`, but only `u-mb-4/6`), so a heading sat flush
  against the thing below it. Check a utility exists before reaching for it.
- **Never widen a shared CSS rule to "cover more cases" without sweeping.**
  Doing that to the icon-alignment rule shrank `.rail-card-head`, which carries
  a full-width border.
- **Browser geometry measurements are worthless when the Browser pane is
  hidden** — the viewport reads 0×0 and every rectangle is a lie. Assert
  `window.innerWidth` is non-zero before trusting a number.
- **When a UI bug measures fine here but Sam still sees it, suspect his cache.**
  Assets are now content-hash versioned (`app.css?v=…`) precisely because that
  cost a round trip.

**Working with the designer.** Deliveries land in a folder with a
`CHANGES-round-N.md`. They have been high quality, but **verify the changelog
against the file** — a rule recorded as "adopted" in round 2 has been absent
from every delivery since, and our `/* Project addition */` block at the end of
`app.css` is the only thing holding that fix. Twice their markup shipped a
control that works in a static mock but is inert in a live app (a `.modal-close`
class that was never used; a drill arrow as a `<button>` that is documented to
navigate). Read their markup as a mock, not as production HTML.

**The discipline.** Author a planning package → do an authoring consistency
review → **Sam approves before any code**. Never self-approve a package you
wrote. It has caught real contradictions every time.

## Running it

`docs/manual-testing.md` is the how-to. A throwaway project and database were
used this session:

- project `/tmp/cromwell-uidemo`, database `cromwell_uidemo` on the
  `cromwell-pg-dev` container, server on `127.0.0.1:8800`
- both are scratch and can be dropped

Integration tests skip unless `CROMWELL_TEST_DATABASE_URL` is set, so a green
`go test ./...` on a machine without Postgres proves less than it looks.
